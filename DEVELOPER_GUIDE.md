# Техническое руководство для разработчиков

## 📋 Обзор проекта

**Что это:** Веб-приложение для анализа техники катания на горных лыжах через обработку видео.

**Как работает:**
1. Пользователь загружает видео своего катания
2. Система анализирует позу лыжника (углы коленей, корпуса)
3. Сравнивает с эталоном профессионального катания
4. Выдает рекомендации по улучшению техники

**Текущее состояние:**
- ✅ Готов Python-модуль для обработки видео (`ski_analyzer/`)
- ✅ Работает анализ и сравнение с эталоном
- ⬜ Нужен веб-API (бэкенд)
- ⬜ Нужен веб-интерфейс (фронтенд)

### Для бэкенд-разработчика

#### 1. Создать REST API (FastAPI/Flask)

**Обязательные эндпоинты:**

##### `POST /api/v1/analyze`
Загрузка и анализ видео пользователя

**Запрос:**
- `Content-Type: multipart/form-data`
- Поле: `video` (файл, форматы: MP4, MOV, AVI)
- Опционально: `user_id` (string) - ID пользователя

**Ответ (200 OK):**
```json
{
  "status": "success",
  "task_id": "uuid-задачи",
  "message": "Видео принято в обработку"
}
```

**Обработка:**
- Сохранить видео во временную директорию
- Запустить асинхронную обработку (Celery/фоновый поток)
- Вернуть `task_id` для отслеживания статуса

##### `GET /api/v1/status/{task_id}`
Проверка статуса обработки

**Ответ (200 OK):**
```json
{
  "status": "processing" | "completed" | "failed",
  "progress": 0-100,  // процент выполнения
  "result": null | { ... }  // если completed
}
```

**Статусы:**
- `processing` - видео обрабатывается
- `completed` - обработка завершена, результат готов
- `failed` - произошла ошибка

##### `GET /api/v1/result/{task_id}`
Получить результат анализа

#### 4. Очередь задач (рекомендуется)

**Для обработки видео используйте:**
- **Celery** (рекомендуется) - для продакшена
- **RQ** (Redis Queue) - проще в настройке
- **Фоновые потоки** - для MVP/тестирования

**Пример с Celery:**

```python
from celery import Celery

celery_app = Celery('ski_analyzer')

@celery_app.task
def process_video_task(video_path: str, task_id: str):
    try:
        pipeline = SkiAnalysisPipeline()
        result = pipeline.analyze_user_video(video_path)
        
        # Сохранить результат в БД/кэш
        save_result(task_id, result)
        
        return {"status": "completed", "result": result}
    except Exception as e:
        save_error(task_id, str(e))
        return {"status": "failed", "error": str(e)}
```

## 🔄 Поток работы (User Flow)

```
1. Пользователь заходит на сайт
   ↓
2. Загружает видео (фронтенд → POST /api/v1/analyze)
   ↓
3. Бэкенд сохраняет видео, запускает обработку, возвращает task_id
   ↓
4. Фронтенд начинает опрос статуса (GET /api/v1/status/{task_id})
   ↓
5. Бэкенд обрабатывает видео:
   - Извлечение позы (YOLO) - ~30-60 сек
   - Вычисление углов - ~5 сек
   - Обработка данных - ~5 сек
   - Сравнение с эталоном - ~1 сек
   ↓
6. Бэкенд сохраняет результат, обновляет статус на "completed"
   ↓
7. Фронтенд получает статус "completed", запрашивает результат
   ↓
8. Фронтенд отображает результаты пользователю
```

## 📊 Форматы данных

### Углы, которые анализируются

```typescript
type AngleType = 
  | "left_knee"      // Левое колено
  | "right_knee"     // Правое колено
  | "left_body"      // Левая сторона корпуса
  | "right_body";    // Правая сторона корпуса
```

### Пороги анализа

- **ABS_THRESHOLDS**: Абсолютные пороги отклонения (в градусах)
  - `left_knee`: 10°
  - `right_knee`: 10°
  - `left_body`: 15°
  - `right_body`: 15°

- **K_STD**: Множитель стандартного отклонения (обычно 2-3)
- **BAD_PERCENT_THRESHOLD**: Порог для критичности (обычно 20%)

## 🛠️ Технические детали

### Требования к видео

- **Формат:** MP4, MOV, AVI
- **Разрешение:** минимум 720p (лучше 1080p)
- **Ракурс:** передний (фронтальный) - обязательно
- **Длина:** 5-60 секунд (оптимально 15-30 сек)
- **Максимальный размер:** 200 MB (рекомендуется)

### Время обработки

- **Короткое видео (10-15 сек):** ~1 минута
- **Среднее видео (30 сек):** ~2 минуты
- **Длинное видео (60 сек):** ~3 минуты

*Зависит от мощности сервера и наличия GPU*

### Ошибки и их обработка

**Частые ошибки:**

1. **Неверный формат видео**
   - Ответ: `400 Bad Request`
   - Сообщение: "Неподдерживаемый формат видео. Используйте MP4, MOV или AVI."

2. **Лыжник не обнаружен на видео**
   - Ответ: `422 Unprocessable Entity`
   - Сообщение: "Не удалось обнаружить лыжника на видео. Убедитесь, что видео снято с переднего ракурса."

3. **Видео слишком короткое/длинное**
   - Ответ: `400 Bad Request`
   - Сообщение: "Длина видео должна быть от 5 до 60 секунд."

4. **Ошибка обработки**
   - Ответ: `500 Internal Server Error`
   - Сообщение: "Произошла ошибка при обработке видео. Попробуйте позже."

## ❓ FAQ для разработчиков

**Q: Можно ли обрабатывать несколько видео одновременно?**
A: Да, но ограничьте количество параллельных задач (например, максимум 3-5) из-за нагрузки на GPU/CPU.

**Q: Нужно ли сохранять видео пользователей?**
A: Зависит от бизнес-требований. Рекомендуется удалять после обработки для экономии места и соблюдения приватности.

**Q: Как масштабировать систему?**
A: Используйте очередь задач (Celery), несколько воркеров, GPU серверы для YOLO, CDN для статики.

**Q: Можно ли добавить другие виды спорта?**
A: Да, но нужно будет создать новые эталоны и возможно адаптировать анализ углов.

**Q: Как тестировать API?**
A: Используйте Postman, curl, или автоматические тесты (pytest для бэкенда, Jest для фронтенда).
